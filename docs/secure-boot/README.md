# Secure Boot & Unified Kernel Image (UKI)

koob OS uses modern UEFI Secure Boot practices to ensure the integrity of the boot process. Unlike traditional Linux distros that use a shim and GRUB, koob OS boots directly from a single signed UEFI binary known as a **Unified Kernel Image (UKI)**.

## 1. Unified Kernel Image (UKI)
A UKI combines several components into a single `.efi` executable file. This entire file is signed with your custom Secure Boot key.

The components are:
1.  **Kernel Stub**: A small UEFI program that loads the kernel.
2.  **Linux Kernel**: The actual `bzImage`.
3.  **Initramfs**: The initial RAM filesystem (containing `koobd`).
4.  **cmdline.txt**: The kernel command line arguments.
5.  **os-release**: System identification.

### Why bundle them?
By bundling `cmdline.txt` into the signed binary, **an attacker cannot modify kernel parameters** (e.g., `init=/bin/bash` or disabling security modules) to bypass security. The bootloader signature covers the configuration.

## 2. File Explanations

### `cmdline.txt`
Contains the arguments passed to the Linux Kernel at boot.
```text
console=tty0 console=ttyS0 net.ifnames=0 random.trust_cpu=on panic=10
```
- `console=...`: Output logs to both graphical (tty0) and serial (ttyS0) consoles.
- `net.ifnames=0`: Disable predictable interface naming (so we get `eth0` instead of `enp3s0`).
- `panic=10`: Reboot automatically 10 seconds after a kernel panic.

### `os-release`
A standard file (usually found at `/etc/os-release` or `/usr/lib/os-release`) that identifies the operating system. In a UKI, this is embedded as a specific binary section (`.osrel`) so bootloaders can identify the OS without mounting the filesystem.

### Enrollment Files
This directory contains the files generated by `make keys` and formatted for the UEFI BIOS.
- **Location**: `tmp/secure-boot/enroll/`
- **PK (Platform Key)**: The root trust key for your hardware.
- **KEK (Key Exchange Key)**: Used to update the signature database.
- **db (Signature Database)**: Contains the public key that verifies your UKI.
- **.auth files**: These are the keys wrapped in a special authenticated structure that the UEFI firmware accepts. You use these files to "Take Ownership" of the machine in the BIOS/UEFI setup.

## 3. The Boot Process
1.  **UEFI Firmware** initializes.
2.  It checks the signature of `EFI/BOOT/BOOTX64.EFI` (our UKI) against the keys in its internal **db**.
3.  If verified, it executes the UKI.
4.  The UKI extracts the embedded cmdline and starts the kernel.
5.  The kernel mounts the embedded initramfs and starts `koobd`.
