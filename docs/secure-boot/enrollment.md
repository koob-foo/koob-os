# Secure Boot enrollment

## UEFI modes

To understand how koob OS boots, distinguish between the two states of the UEFI firmware:

- **setup mode (development)**: This is the default state of a new VM or a factory-reset motherboard. The **Platform Key (PK)** is missing. Even if "Attempt Secure Boot" is **enabled** in the BIOS, the firmware does not enforce signature checking. This allows your signed UKI to boot immediately for development.
- **user mode (production)**: Once you enroll your **PK**, the firmware transitions to user mode. From this moment on, the firmware **strictly enforces** signature verification. If your UKI is not signed by a key in the `db`, it is blocked.

> [!TIP]
> This is why koob OS "just boots" during your first build: it's running in **Setup Mode**. You only need to do the manual enrollment when you want to "lock" the hardware for production.

## Enrollment preparation

Because **koob OS** is a "Build-it-Yourself" distribution, you use your own local keys for enrollment.

### 1. Locate your keys
The enrollment files are generated by the build system in:
*   **Local**: `tmp/secure-boot/enroll/`
*   **Persistent**: `~/.koob/keys/` (if you moved them there)

> [!IMPORTANT]
> **Trust Ownership**: You should always keep a backup of your Secure Boot keys. If you lose them, you will not be able to sign new UKIs that your hardware trusts.

## Enrollment process

1.  **Enter UEFI setup**: Reboot your device and press `ESC` or `Delete` to enter the BIOS/UEFI configuration menu.
2.  **Enter setup mode**: Navigate to the **Secure Boot Configuration** menu.
    - If the firmware already has keys (e.g., from Microsoft), select **"Reset to Setup Mode"** or **"Delete All Keys"**.
    - This "unlocks" the secure storage and allows you to take ownership of the platform.
3.  **Enroll custom keys**: In the **Advanced Secure Boot Keys** menu, enroll your keys in the following order:
    - **db** (Signature Database): Select **Enroll Signature Using File**.
    - **KEK** (Key Exchange Key): Select **Enroll Signature Using File**.
    - **PK** (Platform Key): Select **Enroll Signature Using File**.

> [!IMPORTANT]
> **File Formats**: If your BIOS "File Explorer" doesn't see your files, or shows an "Unsupported Type" error, use the **`.cer`** files (binary DER) instead of the `.auth` files.

4.  **Verification**: After you enroll the **PK**, the firmware automatically transitions to **user mode**. Secure Boot is now active and enforced.
5.  **Reboot**: From this point forward, the firmware only allows Unified Kernel Images signed by your specific `db` key to execute.

## Deployment helpers
The enrollment files (`.auth` and `.cer`) must be accessible to the BIOS during this process:

- **Automated deployment (libvirt)**: The scripts in `examples/libvirt/` automatically create a FAT-formatted virtual disk (`KOOB_KEYS`) containing these files and attach it to the VM.
- **Manual VirtualBox/KVM**: Manually attach a second drive (formatted as FAT) containing the enrollment files.
- **Physical hardware**: Copy the `enroll/` directory to a FAT32-formatted USB drive.

## Reverting Changes (Factory Reset)

Enrolling your own keys is a **non-destructive** operation for the hardware. You can always revert your computer to its original state (e.g., to boot Windows or a standard Linux distro).

1.  **Enter UEFI Setup**: Go to the **Secure Boot** menu.
2.  **Delete Keys**: Select **"Delete All Keys"** or **"Clear Secure Boot Keys"**. This returns the firmware to **Setup Mode**.
3.  **Restore Factory Keys**: Select **"Restore Factory Keys"** or **"Load Default PK"**.
    - This restores the original Microsoft KEK and CA keys.
    - Your system will now boot standard operating systems again.
